## 1. วิธีใช้เอกสาร

### 1.1 สถานะการทดสอบ

| สัญลักษณ์ | สถานะ | ความหมาย |
|---|---|---|
| ⏳ | **รอดำเนินการ (Not Run)** | ยังไม่ได้ทดสอบ — **ทุกกรณีระดับเว็บไซต์ (หัวข้อ 3–18) อยู่ในสถานะนี้** |
| 🧪 | ผ่านบนเครื่องจำลอง | ใช้กับ TC-DB เท่านั้น: ผ่านบน PostgreSQL 16 + Supabase shim · ต้องรันซ้ำบน Supabase จริงก่อนนับเป็น ✅ |
| ✅ | ผ่าน (Pass) | ผลจริงตรงกับผลที่คาดหวัง |
| ❌ | ไม่ผ่าน (Fail) | ผลจริงต่างจากที่คาดหวัง → บันทึกข้อผิดพลาดตามหัวข้อ 21 |
| ⛔ | ทดสอบไม่ได้ (Blocked) | ฟังก์ชันที่ต้องใช้ยังไม่พร้อม |
| ➖ | ไม่ทดสอบ (N/A) | ตัดออกจากขอบเขตพร้อมเหตุผล |

### 1.2 ระดับความสำคัญ

- **P1** — ต้องผ่านก่อนส่งงาน (ฟังก์ชันหลัก, ความปลอดภัย, เงิน/สต็อก/คะแนน)
- **P2** — ควรผ่าน (UX, กรณีขอบ)

### 1.3 กติกาการบันทึกผล

1. บันทึกผลจริงในคอลัมน์ "ผลจริง" เฉพาะเมื่อทดสอบจริงแล้ว พร้อมวันที่และผู้ทดสอบ
2. **ห้ามเปลี่ยนสถานะเป็น ✅ โดยไม่ได้ทดสอบจริง**
3. แนบภาพหน้าจอสำหรับกรณีที่ไม่ผ่าน
4. ถ้าแก้ Business Rule (เช่น ค่าส่ง, อัตราคะแนน) ให้แก้ "ผลที่คาดหวัง" ในเอกสารนี้ก่อนทดสอบ
